# Spark — Product & Marketing Strategy

Research synthesis for building and launching a dating app in 2025–2026. Sources include industry benchmarks (Adjust, PG Dating Pro), competitor filings (Match Group SEC), and monetization analysis (Bumble, Hinge, Tinder).

---

## 1. Executive summary

The dating category is **mature and expensive**: global CPI rose to ~$2.76 (2025), D30 retention for mainstream apps sits around **4–8%**, and leaders are pushing **ARPPU over user growth** (Bumble FY2025: −9.9% revenue, ARPPU +1.9%).

**Spark’s wedge:** drag-to-target discovery (distinct from patented swipe-left/right), fast onboarding, and a **liquidity-first launch** in one city before scaling.

**North-star metric:** % of new users who reach **first mutual match + first message within 24 hours**.

## 2. Product structure map

### 2.1 Layered architecture (industry standard)

| Layer | Purpose | Spark status |
|-------|---------|--------------|
| **Identity** | Auth, age gate, profile, photos, intent | Onboarding MVP ✅ |
| **Discovery** | Queue, filters, ranking, limits | Drag deck + filters ✅ |
| **Interaction** | Like, pass, match, chat | ✅ |
| **Safety** | Report, block, guidelines, verification | Safety center ✅ (prototype) |
| **Monetization** | Subscriptions, consumables, paywalls | Spark+ screen ✅ (prototype) |
| **Growth** | Referrals, ASO, notifications | Referral CTA ✅ (prototype) |
| **Trust** | Photo verify, moderation | Roadmap |

### 2.2 Core user loop

```
Install → Onboard (intent + profile) → Discover → Like/Pass → Match → Message → Return (D1/D7)
```

**Critical path:** Every screen should push users toward **one quality action per session** — not endless browsing without matches.

### 2.3 Screen inventory (Spark)

| Screen | Competitor analog | Job to be done |
|--------|-------------------|----------------|
| Onboarding | Tinder rules + Hinge prompts | Trust, intent, profile quality |
| Discover | Tinder home | Core loop — drag to heart/trash |
| Likes | Tinder Gold / Bumble Beeline | Monetization anchor — “see who liked you” |
| Matches | All apps | Retention — conversations |
| Chat | Bumble icebreakers | Activation — first message |
| Profile | Settings hub | Edit, safety, subscription |
| Spark+ | Gold / Premium / Hinge+ | Convert free → paid |
| Safety | Bumble safety center | Trust & compliance |

## 3. Competitive positioning

| App | Positioning | Monetization anchor |
|-----|-------------|---------------------|
| **Tinder** | Scale, casual, swipe culture | See who liked you, unlimited likes, Boost |
| **Bumble** | Women message first, safety | Beeline, Spotlight, Premium filters |
| **Hinge** | “Designed to be deleted,” prompts | Roses, unlimited likes, HingeX placement |
| **Spark** | Intentional drag, playful UX | Spark+ (see likes, unlimited, boost, rewind) |

### Differentiation (legal + product)

- **Do not** clone Tinder swipe patents/trademarks — Spark uses **drag-to-target** (trash / heart).
- **Do** borrow proven patterns: blurred likes grid, match modal, icebreaker chat, freemium daily limits.
- **Niche option:** launch as “designers & creatives in [city]” or “slow dating” to improve liquidity and word-of-mouth.

## 4. Monetization strategy

### 4.1 Industry model (freemium stack)

> Free tier must produce **real matches** or the marketplace empties. Paid tier sells **speed and control**, not access to matching itself.

| Revenue rail | % of category revenue | Spark implementation |
|--------------|----------------------|----------------------|
| **Subscriptions** | ~69% (2025) | Spark+ monthly/annual |
| **Consumables** | Boosts, Super Likes | Boost, Spark Note (pre-match message) |
| **Ads** | Small until scale | Defer until 100k+ MAU |

### 4.2 Spark+ feature bundle (benchmarked)

| Feature | Tinder | Bumble | Hinge | Spark+ |
|---------|--------|--------|-------|--------|
| See who liked you | Gold+ | Beeline | Hinge+ | ✅ Anchor feature |
| Unlimited likes | Plus+ | Premium | Hinge+ | ✅ |
| Rewind / undo | Plus | Rematch | — | ✅ |
| Boost (30 min visibility) | Boost | Spotlight | Boost | ✅ |
| Advanced filters | Platinum | Premium | HingeX | ✅ |
| Read receipts | Platinum | Premium | — | Roadmap |
| Pre-match note | — | Opening Move | Rose + comment | Spark Note |

### 4.3 Pricing guidance (2026 benchmarks)

| Tier | Market range | Spark launch suggestion |
|------|--------------|-------------------------|
| Weekly | $9–15 | $12.99/week (impulse) |
| Monthly | $15–20 basic, $35–50 top | **$14.99/mo** Spark+ |
| Annual | $100–200 (best value) | **$99.99/yr** (~$8.33/mo) |

**Paywall triggers (event-based, highest conversion):**
1. User taps blurred like on **Likes** tab
2. Daily like limit reached (10/day free — industry pattern)
3. After 3rd match in a session (momentum)
4. Before Boost use

## 5. Marketing & growth strategy

### 5.1 Launch sequence (geo-density first)

Dating apps fail nationwide launches with thin liquidity. **Launch one metro**, then expand.

| Phase | Goal | Tactics |
|-------|------|---------|
| **0 — Beta** | 500 profiles, 50% D1 retention | Friends, local events, one university/work hub |
| **1 — City** | 5k users, balanced gender ratio | Instagram/TikTok creators, referral credits |
| **2 — Region** | Repeat city playbook | ASO, Apple Search Ads, Meta ROAS campaigns |
| **3 — Scale** | LTV:CAC > 1.5 | Paid UA only when D30 cohorts prove ROAS |

### 5.2 Channel mix

| Channel | Role | Notes |
|---------|------|-------|
| **ASO** | Always-on organic | Keywords: dating, singles, [city], relationships |
| **Referral loop** | Lowest CAC | “Give 1 week Spark+, get 1 week” |
| **TikTok / Reels** | Creative-led UA | UGC date stories, not explicit ads |
| **Meta** | Volume + lookalikes | Optimize to **subscription**, not install |
| **Apple Search Ads** | High intent | “dating app” search terms |
| **Events** | Niche apps | Speed dating, gallery nights (Hinge-style IRL) |

### 5.3 Brand & messaging

**Tagline options:**
- “Match with intention.”
- “Drag your heart into it.”
- “Dating, without the mindless swipe.”

**Creative angles:**
- Before/after: chaotic swipe app vs. intentional Spark drag
- Safety-first: “Meet in public” house rules (Bumble trust pattern)
- Social proof: match stories (with permission)

### 5.4 Key metrics (benchmarks)

| Metric | Industry range | Spark target (MVP) |
|--------|----------------|-------------------|
| Install → registration | 60–80% | >70% |
| Profile completion | 40–60% | >50% |
| D1 retention | 25–35% | >30% |
| D7 retention | 10–15% | >12% |
| D30 retention | 4–8% | >6% |
| Free → paid (30d) | 2–5% | >3% |
| ARPPU (monthly) | $20–27 | $15+ at launch |
| CPI (global) | ~$2.76 | Track by city |

**Funnel to instrument:**
`Impression → Install → Register → Profile complete → First like → First match → First message → D7 return`

## 6. Retention & engagement

| Mechanic | Why it works | Spark |
|----------|--------------|-------|
| Daily like limits | Creates scarcity → upgrade | 10/day free |
| “Your turn” badge | Reduces ghosting | Matches tab ✅ |
| Match expiry (24h) | Urgency (Bumble) | Optional premium extend |
| Icebreaker prompts | Lowers first-message friction | Chat ✅ |
| Push: new match / message | Brings users back | Roadmap |
| Boost / surge windows | DAU spikes | Boost button ✅ |

## 7. Safety & trust (non-negotiable)

- House rules at onboarding ✅
- Report / block in chat (roadmap)
- Photo verification badge (roadmap)
- Safety center with tips + resources ✅
- Age gate 18+ (roadmap)
- Moderation queue for new profiles (industry: <24h review)

## 9. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Tinder IP (swipe patents) | Keep drag-to-target; own branding |
| Cold start / empty deck | Launch single city; seed events |
| Gender imbalance | Waitlist + invite waves per cohort |
| High CPI | Referrals + organic before paid scale |
| Trust / harassment | Safety center, reporting, moderation |
| Swipe fatigue trend | Intentional UX + prompts over volume |
